What: "Insufficient Verification of Data Authenticity" (CWE-345). A multi-log
threshold bypass in sigstore-go's verification path. When a verifier is
configured with more than one transparency log or signed certificate timestamp
(WithTransparencyLog(N>1) or WithSignedCertificateTimestamps(N>1)) for
defence-in-depth, the implementation counts verified witnesses per log entry or
per validation path rather than per distinct log authority. An attacker who
controls a single compromised transparency log can therefore satisfy the whole
N-of-M threshold on their own -- by creating multiple entries at different
indices, or by verifying across multiple certificate chains / embedded SCTs --
and forge a signature or certificate that passes the multi-log policy. Impact is
integrity only (accepting a forged artifact); there is no confidentiality or
availability effect. Attack vector Network, complexity High, no privileges or
user interaction. Cosign is explicitly NOT affected because it uses a threshold
of 1.
Fix available: sigstore-go 1.2.0 (vulnerable: < 1.2.0).
For cyber-dojo: github.com/sigstore/sigstore-go/pkg/verify is part of the
sigstore signature-verification toolchain; it is linked transitively through the
Docker image-signing and attestation toolchain (cosign / docker buildx) bundled
in the dind image, not through any code cyber-dojo writes. Exploiting the bypass
requires two things the runner never provides: a verifier configured with a
multi-log threshold greater than 1, and an attacker who operates a compromised
transparency log that the verifier trusts. The only in-image consumer is cosign,
which uses a threshold of 1 and is explicitly unaffected; the runner itself
performs no multi-log sigstore verification and operates no transparency log.
User code runs inside a sandbox container with --net=none, --user=41966:51966
and --security-opt=no-new-privileges, so it cannot reach any network endpoint,
submit log entries, or influence any signature-verification policy.
Verdict: Not exploitable. The bypass affects only a verifier configured with an
N>1 log threshold and additionally requires control of a trusted transparency
log; the bundled cosign consumer uses threshold 1 and is unaffected, and the
runner does no multi-log verification of its own. The real fix is bumping
sigstore-go to 1.2.0+.
